# 外部模型接入预留

客户端继续使用 dianjie.org 的统一鉴权接口，不直接连接供应商，也不保存供应商密钥。Mac mini 内部的 `ModelAdapter` 边界允许以后接入其他模型运行时或外部供应商。

当前已提供本地进程适配器，以及默认关闭的 `OpenAICompatibleAdapter` 骨架，后者支持聊天（含兼容的视觉输入）、向量、生图、语音合成。语音识别的 multipart 请求、供应商专用音频理解、流式输出和异步任务协议需要对应适配器，不能直接假定兼容。

## 启用边界

- 当前生产路由仍使用 Mac mini，尚未配置或启用外部供应商。外部适配器不是自动降级路径。
- 运维固定 HTTPS 地址、上游模型和独立的 `POINTVERSE_PROVIDER_*` 密钥环境变量；客户端不得指定地址或密钥。
- 执行必须同时满足适配器启用和本次请求明确允许外部处理。隐私模式始终禁止外部请求；登录模式也不能被当作第三方处理的默认授权。
- 不转发用户登录令牌或内部网关密钥，不跟随供应商重定向，限制请求时限与响应大小。

## 后续接入约定

服务端维护“公开模型别名 → 供应商、实际模型、能力、输入限制”的白名单。客户端选择公开别名，不感知上游地址。能力列表只公布已配置且可用的模型，并显示本机或外部执行来源。

供应商适配器负责格式转换；统一层负责鉴权、用户配额、费用上限、限流、超时和取消。外部能力不能未经授权自动重试到另一家供应商；生图等收费任务沿用用户隔离、幂等键和任务状态，避免重复计费。

向量结果携带模型版本和维度，切换供应商必须重新建立对应索引。模型返回的来源信息应保留，便于用户理解执行位置。日志不记录输入正文、音频、图片和供应商密钥。

这些配置目录、费用控制和用户授权界面属于后续启用工作；本次仅保留接入边界，不会调用或付费使用任何外部模型。
