# 点界 PointVerse · 产品 Backlog

版本 v0.8 · 2026-09-08 · 对应《产品文档 v0.8》

本表是基于最新讨论的建议执行顺序。未获得代码库、团队产能与已完成任务清单，全部条目状态为**待开始／待验证**；负责人仅为建议角色。既有明确原则：中文名点界、本地优先、用户主动 Play、保留原始内容、结果由用户选择沉淀。新增功能、排序、规模与验收数字均为建议。

## 1. 如何读优先级与重要度

| 维度 | 定义 |
|---|---|
| P0 | 私人内测前必须完成，或必须先消除的不确定性；不表示所有事项同时开工 |
| P1 | 闭环可用后的下一轮增强，或扩量／收费前必做 |
| P2 | 有留存、需求或技术证据后启动 |
| P3 | 长期探索，当前只保留假设与触发条件 |
| 重要度 5 | 决定核心价值、数据安全或用户控制权 |
| 重要度 4 | 显著影响持续使用、差异化或商业可持续性 |
| 重要度 3 | 改善体验或提供尚未验证的增长机会 |
| 重要度 2／1 | 局部优化／装饰性收益，目前未列入核心计划 |

排序原则：先处理价值与不可逆数据风险，再按依赖做最小闭环；高重要度不等于高紧迫性。暂不使用 RICE 数字排名，因为没有可信覆盖人数、影响和置信度数据。工作量为相对复杂度：S 单一流程；M 多模块联动；L 跨端、权限或新服务；XL 需继续拆分。它们不是人日估算。

阶段：G0 定义与原型 → G1 私人内测 → G2 留存和付费验证 → G3 分享与开放试点 → G4 价值交换探索。

## 7. 指标、发布门与复审

**北极星建议：每周有效再发现次数。** 用户重新打开至少7天前的点，并保存新点、确认关系或导出使用；同一用户同一源点每日去重。纯打开、自动生成、自动关系不计入。7天是初始口径，新用户首次闭环单独统计。

同时观察首次闭环完成率、旧点找回成功率、结果保留后再使用率、内测跨周回访、用户自评有用、每次有效结果成本。分享阶段另看有内容的回应与二次复用；不能将点击和点赞直接认定为共鸣。

**阻断发布：**未授权上传、已保存内容丢失、恢复不可用、源点被模型覆盖、越权访问。性能与模型质量不达标时记录设备和样本，再明确降级范围。统计默认仅在本地，外发分析需独立说明与控制，不能采集原始点内容。

**每周复审：**更新真实状态、负责人、依赖与验收证据；依据失败案例调整范围。只有证据改变才升降优先级，不因新想法有吸引力而挤掉可靠性工作。完成须附演示、测试记录或用户反馈，不能以“代码写完”代替验收。

### 新增数据与验收细则

- Point标题可为空，列表回退显示时间与模态；自动摘要不充当用户命名。B04补原始模态、派生来源与授权引用；共振点复用Point，不引入独立内容孤岛。
- ShareSnapshot保存实际内容范围、受众与允许操作；转换与改编权限分开。B23负责服务和权限，B36负责交互原型，B37负责显影转换，B38负责回应沉淀，避免重复开发。
- 盲盒外观不隐藏必要控制：受众和授权对发送者明确可见；接收者能知道可用操作及是否涉及云端。链接预览、通知、缓存缩略图不泄露未揭示正文；这项纳入B23验收。
- B37新增检查：转写错误可识别和修正；原音始终可访问（授权有效时）；发送者未允许外部AI处理时不能提交云端；失败可以退回原始载体。
- B38新增检查：系统只记录“用户声明有共鸣”和实际回应，不把相似度当作双方共鸣；回应保存不得自动触发公开发布；授权变化影响后续读取。
- B15内测门新增无标题保存与时间线回看检查；B23／B37／B38开放试点单独过权限门，不混入私人首版范围。

### 本轮实验的判断口径

捕获观察从“开始记录到成功保存”的完整过程，区分文字输入耗时与系统保存延迟；不把多记几条直接当作理解增加。盲盒观察是否理解、是否愿意打开及打开后是否有价值，打开率不是唯一成功指标。共振点观察有实质内容的回应、主动保留与之后再用；科学用途的事实核验不能被“有美感”或“有共鸣”取代。

“私人／定向／小组／跨领域”是用户可选择的范围。公开广场继续归B33远期探索；B39只做自愿配对，不开发全网推荐系统。统一美感评分、自动推断阶层以及把私人点默认加入匹配均不纳入方案。
