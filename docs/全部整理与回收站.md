# 全部整理与回收站

2026-10-22，build 24 上传后的工作区实现，尚未发布。

## 入口和范围

- 想法页右上角「整理」，或宇宙的分类页「全部重新整理与回收站」。即使没有活跃想法，也能进入回收站恢复。
- 范围是当前 AppContainer 资料库中的全部活跃 Point，不受想法列表搜索、时间、说话人等筛选影响。
- 正式资料库与独立测试资料库共用实现，但连接与附件目录仍完全隔离，页面显示当前范围。

## 不同维度的整理

| 维度 | 实现 | 人工信息 |
| --- | --- | --- |
| 知识领域／主题 | 使用当前文本模型重新提取主题，由现有别名表匹配 LCC；两者一起重新生成，包括已有自动结果的记录 | 单维度人工覆盖仍优先，两维度均为人工指定时跳过模型 |
| 表达性质 | 重新读取全量活跃内容，以现有本地关键词规则按问题、设想、计划、观察、方法、感受分组；不新增模型判断或数据库快照 | 保留人工表达性质 |
| 项目 | 重新读取并按人工指定的项目分组；不推测项目、不生成项目名称 | 全部保留 |

整理后可逐组查看原文。知识领域／主题的有效自动结果直接生效，脑图、宇宙沿用现有分类投影；其他维度的重新分组不改变星球归属。

### 批量执行

- 用户确认后获取全量快照，逐条调用当前文本模型，沿用共享模型执行门，不同时运行多个本地模型。
- 网络模型仍遵循现有授权；每条发送标题及正文前 600 字符，确认中提示可能产生费用。不额外上传整库或附件。
- 此流程先生成不落库的结果，成功后独立保存；调用失败或输出不合法不覆盖旧分类。
- 写入检查 Point 的活跃状态和内容 revision，预览后已改变或已移入回收站的记录跳过。
- 显示进度，可以停止；离开页面取消后续任务。已经完成的结果保留。连续 3 条调用失败停止，避免无效请求扩大。
- 结果逐条持久化，但结束／取消时统一发分类通知，避免每条完成都重建宇宙。

## 清理候选不等于无意义

第一版采用本地保守规则，不让语言模型自动判断内容价值：

1. 标题与正文完全一致的纯文字记录，按创建时间保留最早的一条，后续记录列为候选。同一时间按 ID 稳定排序。
2. 没有标题、文字、附件及后续对话的空白记录列为候选。
3. 有语音、图片或后续对话的记录不自动列入；未转写、未识图不代表无意义。
4. 短句、情绪、未分类、不常访问、低相似度都不是清理依据。

候选显示理由和原文入口，默认全部不选。用户勾选并确认后才移动。对其他自己认为无用的内容，可在想法列表滑动或详情菜单手动「移入回收站」。不进行语义相似去重，不自动合并原文。

## 回收站与数据安全

数据库迁移 `v17-point-trash` 为 `points` 增加可空的 `trashed_at`、`trash_reason` 和索引。移入时只更新标志，不执行 DELETE，也不移走或删除附件文件。

- 正常想法列表、搜索、地图、语义关联候选、回忆及待转写／待向量化扫描排除回收站内容。
- 原始消息、语音、照片、转写、主题、人工分类、向量、地理坐标、关系继续保留。原文查询仍可供回收站只读预览使用。
- 清理请求携带预览时的 revision；有后续编辑则跳过。批量移动在一个事务中执行。
- 回收站支持逐条恢复与恢复全部；恢复是清除标记，不重建 Point，原 ID 和关系不变，并恢复待转写／待向量化调度。
- 普通列表和详情原来的永久删除入口改为可恢复移动；底层永久删除方法仍供已有明确测试清理等内部流程使用，不在新回收站提供永久删除或定期清空。
- 既有「清空独立测试数据库」仍是单独的明确破坏性操作，继续校验精确测试库路径；它也会清空该测试库中的回收站，但不会触碰正式库。

## 验证和边界

自动测试覆盖：精确去重的稳定性、短句和媒体保护、回收站排除搜索／地图／关联向量／回忆、附件与分类／坐标保留、恢复、幂等、跨资料库隔离、过期 revision 拒绝移动或分类写入。

尚未实现：模型辅助价值评分、清理建议历史、撤回整轮自动分类、批量项目自动识别、回收站中附件播放预览、永久清空。网络费用、模型输出质量、长批量取消和页面交互仍需真机／Mac 人工验证。
