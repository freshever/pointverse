## 判断

当前布局**不能让差异足够大的内容均匀分布在整个地球上**。这不是测试词句不够分散，而是算法明确把所有点限制在半径 `0.28 rad ≈ 16°` 的球冠内；即使输入是完全无关的主题，也不可能离开这块区域。

“更密集”和“铺满地球”是两个不同的目标。若产品希望既有主题内部密集、又让不同主题占据不同大陆，应先在 E5 空间做社区发现，再把社区中心分布到球面各区域；每个社区内部保持紧凑。当前直接将所有 Point 放进一个球冠，不可能实现这一点。

`Recall@5 = 0.113` 也说明现有球面位置没有很好保留高维近邻。需要社区层级、固定语义轴和图邻域保真优化，不能把当前坐标解释为可靠的语义地图。

本实验使用原始 PyTorch 权重而非 App 的 INT8 Core ML 权重；两者可能有数值差异。布局脚本是 Swift 实现的数学复现，不直接读取用户数据库，也不能代替真机端到端测试。

## v4 对照实验（同一批 48 条词句）

根据上述结论，`e5-distributed-communities-v4` 先用 E5 余弦距离确定性选出语义群，再将群中心布到全球，群内限制在约 0.22 rad 范围。Demo JSON 已重新生成；上面的 v3 数据保留为历史基线。

| 指标 | v3 单球冠 | v4 分布式语义群 |
| --- | ---: | ---: |
| 语义群 | 未区分 | 12 |
| 纬度范围 | -16°～+16° | -68.9°～+78.0° |
| 经度范围 | 74°～106° | -176.8°～+162.0° |
| Neighbor Recall@5 | 0.113 | 0.354 |
| 同主题平均夹角 | 16.86° | 68.31° |
| 异主题平均夹角 | 19.68° | 91.25° |

v4 已经能够让不同语义群出现在全球不同区域，同时球面近邻保真度提高。但它不保证人工命名的主题一定只有一个群；例如同一主题中的理论问题和实际任务可能被分开。同主题平均夹角仍达到 68.31°，下一步需要更好的社区检测和语义邻域评估，而不是仅追求均匀覆盖。南北纬度尚无 Anchor 语义，不应解释为“抽象/行动”。
